# rr-offline-calc

A self-playing Nuzlocke battle agent for Pokémon Radical Red. (The name is
from the offline damage calculator it grew out of, which is still here.)

The agent plays the game's trainer battles inside a real emulator, from what
the game's own memory says, under Nuzlocke rules: the goal is not to win but to
win without losing anyone. It beats Lt. Surge from a fixed save state losing
nobody, on two different routes, and it is now being taught double battles.

> The damage engine and the trainer data are other people's work. See
> [THIRD-PARTY-NOTICES.md](THIRD-PARTY-NOTICES.md). No ROM, save, or game asset
> is in this repository.

## The agent

Three processes and a hidden fourth.

```
  mGBA (the game)                      Node (the brain)
  ┌──────────────────────┐   state.json   ┌──────────────────────────────┐
  │ tools/lua/           │ ─────────────▶ │ tools/agent.js               │
  │  agent_impl.lua      │                │  decode party records (RAM)  │
  │  reads battle RAM    │   cmd.json     │  build the engine position   │
  │  every frame,        │ ◀───────────── │  plan (tools/lib/*)          │
  │  presses buttons     │                │  check against the oracle    │
  └──────────────────────┘                └──────────────┬───────────────┘
            │ save state, one second into every menu      │
            ▼                                             ▼
  ┌──────────────────────┐                ┌──────────────────────────────┐
  │ tools/headless/oracle│ ◀───────────── │ every legal action, played   │
  │  windowless mGBA core│  ~0.7 s each   │  for real before pressing    │
  └──────────────────────┘                └──────────────────────────────┘
                                          panel: tools/control.js (:8420)
```

**Observation from RAM, not from the screen.** The Lua script reads the battle
structures directly: both active Pokémon, both parties as raw records, stat
stages, status, the enemy AI's committed action, the battle RNG. The brain
decodes the records itself (species, moves, PP, IVs, nature), so the opponent's
real set comes from the game rather than from a spreadsheet, and Hidden Power
types, hidden abilities and mid-fight form changes are read rather than
guessed.

**A battle engine and a port of the enemy AI.** `upstream-calc/src/js/rr-battle.js`
simulates turns on top of the calculator's damage formula: 1074 moves with
their effects, entry abilities, hazards, weather and terrain, multi-hit,
priority, pivots, traps, Substitute, Shed Tail and the rest, verified by an
audit that asks whether the engine *acts on* every effect the data declares
(`tools/audit_mechanics.js`, currently zero gaps). `rr-ai.js` ports the
decision rules of the game's AI (Complete FireRed Upgrade lineage). Graded
against 3,329 real AI decisions recorded from live play, it names the exact
move 76% of the time and the argmax set 89%; the biggest gains came from
finding that the recorded corpus itself was wrong, four separate times.

**A planner that thinks in lines.** Candidate lines are generated by purpose
(open with Fake Out, drop its Attack then leave before you faint, absorb the
Electric move with Volt Absorb and heal, chip then finish), priced by
simulating them, and re-chosen every turn with the previous plan re-offered so
the agent can hold a sequence instead of re-deriving one. A position score
values conditions by what they measurably change: an Attack drop is worth the
damage their real moves no longer do to your living team, a Speed drop is worth
the hits you no longer take first, and a stat move that changes nothing is not
offered at all. Zero faints is the target; a certain non-expendable faint
ranks below every line that loses nobody.

**The game as its own oracle.** Before every press, the brain hands a save
state of the exact menu to a windowless mGBA core and plays the chosen action
and every legal rival for real, about 0.7 s each. This ROM consumes its battle
RNG per call and the state restores it, so the hidden core's answer for an
action *is* the live outcome. The real after-states are scored with the
position score and a rival replaces the plan only when it wins by a clear
margin; on hard turns the top candidates are rolled one turn further. Nothing
appears on screen, which is the rule that makes it legitimate: the player
watching the game cannot tell it is happening.

**Measured, including the failures.** The project's rule is that a change
earns its place by a paired measurement or it stays behind a flag. The harness
runs seeded paired dice so two variants face identical rolls, and
`tools/compare_arms.py` applies McNemar's test. That is how it was learned
that more search loses (four independent times), that the death veto helps
(p = 0.0008 over 120 paired episodes) after a week of suspecting it hurt, and
that the flat penalty for "nothing answers this Pokémon" cannot be tuned in
either direction. `docs/BATTERY-RESULTS.md` and `docs/VALIDATION-LOG.md` keep
the negative results next to the positive ones.

### Status

Rehearsal mode: the player saves before each fight, the agent plays it, and
when it plays a turn wrong the position is replayed from the archive, fixed,
and the save reloaded until it plays the way a strong player would. Lt. Surge
(level cap 34, five Pokémon) is beaten losing nobody from a fixed state, on the
original route and on a new one the solved sequence never took; Erika and the
Rocket Hideout Giovanni have been won live since. Every fight so far has
turned up something the agent could not see, and each is recorded:
`docs/HANDOFF.md` is the current picture and the open list.

Next is double battles, which nothing in the agent plays today. The plan, its
staging and the acceptance test for each stage are in `docs/PLAN-DOUBLES.md`.

This is a personal research setup, not a product. It is bound to one ROM
build's memory layout, to mGBA on macOS, and to a directory of runtime files
under `~/rr-agent`. Anyone wanting to run it should start from
`docs/HANDOFF.md` section 3 and expect to re-derive addresses for a different
build (`docs/SCREEN-MAP.md` shows how they were found).

### Running it

```bash
npm install && npm run build                       # the engine and the calculator page
/Applications/mGBA.app/Contents/MacOS/mGBA <rom>   # then Tools > Scripting > load tools/lua/bootstrap.lua
EXPENDABLE="" node tools/agent.js                  # the brain; watches ~/rr-agent
node tools/control.js                              # optional panel on http://localhost:8420
```

The hidden core needs a local mGBA 0.10.5 source build; `tools/headless/build.sh`
and `docs/HANDOFF.md` section 4 have the recipe. Without it the agent still
plays, on the planner alone.

Tests worth knowing: `node tools/test_plan.js` (planner), `node tools/test_growl.js`
(a regression built from a live mistake), `node tools/audit_mechanics.js`
(engine effect coverage), `node tools/test_ai.js` (the AI port).

## The calculator

Where the project started, and the one part anyone can use without the
emulator setup: an offline Radical Red damage calculator with every trainer
battle pre-loaded, crit-aware KO chances, doubles, save-file import, and the
Pokédex, working from `file://` with no network. It is finished and it is not
the focus any more. `docs/CALCULATOR.md` has the features, the data checks and
how to build it (`npm install && npm run build`, then open
`upstream-calc/dist/index.html`).

## Layout

```
tools/agent.js              the brain
tools/control.js            the panel
tools/lua/                  the actuator (bootstrap.lua loads agent_impl.lua and hot-reloads it)
tools/lib/                  planner: candidates, paths, replan, policy, duels, position, difficulty, oracle
tools/headless/             the windowless core (oracle.c) and its build script
tools/test_*.js, audit_*.js tests and audits; compare_arms.py is the paired-test referee
upstream-calc/src/js/       rr-battle.js (engine), rr-ai.js (AI port), rr-critko.js (crit KO maths),
                            rr-trainers.js, rr-doubles.js, rr-dex.js, rr-save.js (the calculator page)
data/                       the sheet cache, the Pokédex snapshot, curated move effects
docs/                       the notebook
```
